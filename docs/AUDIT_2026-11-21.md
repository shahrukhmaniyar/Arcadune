# Arcadune audit (2026-11-21, version 1.1.1)

No code was changed for this audit, nothing was committed and nothing was released.
The phone was not connected, so everything below comes from reading the code and running the build tools. Each finding says how sure it is:

- **Confirmed**: proved by reading the exact code path, or reported by a tool.
- **Likely**: the code allows it, but it has not been reproduced on a phone yet.

## What was run

| Check | Result |
|---|---|
| Unit tests, every module and every build variant (`gradlew test --rerun`) | **154 unique tests, 0 failures, 0 errors, 0 skipped** (counts read from the XML reports) |
| Android lint, release build (`lintFreeBundleRelease`) | **Fails: 1 error, 38 warnings** |

## 1. HIGH: nothing tests the screens, so crashes like 1.1.0's reach users (Confirmed)

**Problem.** 1.1.0 shipped with the Settings choice dialogs and Change Cores crashing. No automated check opens a screen: there are no UI tests, lint is red, ktlint is red, and CI never runs. The only safety net is a person tapping around before a release, and that missed it.

**Fix (in this order, cheapest first):**
1. **A guard test for the exact 1.1.0 bug.** Add a unit test that scans the source and fails when a `verticalScroll` or `LazyColumn` without a height limit sits inside an `ArcaduneDialog { ... }` block. It takes about 30 lines and runs in a second.
2. **A scripted phone smoke test.** Commit `scripts/smoke-test.ps1`, a cleaned-up version of the script used for the 1.1.1 check. It opens every Settings screen and dialog, the pause menu and each in-game tile, in portrait and landscape, and fails on any line in `logcat -b crash`. Make it a required step in the release checklist.
3. **Compose UI tests with Robolectric** for the Settings pages and dialogs, so they also run on a PC without a phone.
4. **Make lint and ktlint green**, then run `test`, `lint` and `ktlintCheck` on every push (see finding 4 for the CI file).
5. **A written release checklist** in `docs/RELEASE_CHECKLIST.md`: tests, lint, smoke test on the phone, then release.

## 2. HIGH: a failed save read can wipe a real save (Confirmed code path; rare in practice)

**Problem.** `SavesManager.getSaveRAM` (`retrograde-app-shared/.../saves/SavesManager.kt:14-31`) retries three times and then returns `null` on any read error, which is the same answer as "this game has no save". The game then starts with empty save memory. When the player exits, `GameViewModelSaves.writeSaveSnapshot` (`lemuroid-app/.../viewmodel/GameViewModelSaves.kt:115`) always writes that memory back over the old `.srm`. A temporary storage error at launch, such as an SD card waking up or the phone being low on space, turns into a lost save.

**Fix.**
- Make `getSaveRAM` return three distinct answers: no save, a save, or a read error. On a read error, stop the launch with the existing `GameLoaderError.Saves` message instead of starting fresh.
- Keep one previous copy: before replacing `Game.srm`, rename the old file to `Game.srm.bak`. This needs one small change in `writeBytesAtomic` for saves only.

## 3. HIGH: two quick taps on a game can start it twice (Likely)

**Problem.** `GameLauncher.launchGameAsync` (`lemuroid-app/.../shared/game/GameLauncher.kt:23-54`) starts a background job for each tap and has no "already launching" guard. The game-process lock is only taken once the game process has started, so two taps a fraction of a second apart both pass the check, and two game screens start in the same process. Emulator cores are one-per-process native code, so the likely result is a crash or a corrupted save. The same function also:
- calls `startActivityForResult` from a background thread;
- holds the screen for up to 3 seconds while it waits. If you rotate during that wait, the result goes to a dead screen, and that session's play time is not recorded.

**Fix.** In `GameLauncher`, keep an `AtomicBoolean launchInFlight`. Set it on the first tap and ignore further taps while it is set. Clear it in `onActivityResult`, or after a timeout. Do the wait off the main thread, then switch to the main thread and use the current activity to start the game.
**To confirm on the phone:** double-tap a library tile quickly 10 times and watch `logcat -b crash`.

## 4. HIGH: the GitHub "Publish" workflow would release debug-signed APKs (Confirmed, not triggered)

**Problem.** `.github/workflows/publish.yml` runs on every tag push, including `cores-*` tags. It decodes a `release.jks` file, but the build reads the key from `keystore.properties`, which the workflow never creates. The build therefore falls back to the debug key and publishes a "Pre-release" with `Arcadune.apk` and `Arcadune-full.apk`. Anyone who installed those could never update to a real release, because Android refuses updates signed with a different key. It hasn't happened only because Actions is disabled on the repo. It also uses `upload-artifact@v3`, which GitHub has retired.

**Fix.** Delete `publish.yml`, since releases are made by hand and verified with sha256. If an automated build is wanted later, write a new one that creates `keystore.properties` from secrets, runs only on `v*` tags, and makes a draft release. Replace `checkstyle.yml` with a workflow that runs `test lint ktlintCheck`.

## 5. MEDIUM: two games with the same file name share one save (Confirmed)

**Problem.** Battery saves all go to a single `saves/` folder named after the ROM without its extension (`SavesManager.saveFileNameFor`, `SavesManager.kt:92`). For example, `Sonic.md` (Mega Drive) and `Sonic.gg` (Game Gear) both use `saves/Sonic.srm`, so playing one overwrites the other's save. Save states are fine, because they are kept per core with the full file name.

**Fix.** Keep the RetroArch-style name when it is unique. When two library games would map to the same `.srm`, store the save as `saves/<systemId>/<name>.srm`. When reading, look in the new path first and fall back to the old one. Add a unit test with the Sonic example.

## 6. MEDIUM: downloaded emulator cores are not fingerprint-checked (Confirmed)

**Problem.** The Lite APK downloads native `.so` cores from the `cores-2` release. `CoreUpdaterImpl` (`lemuroid-app-ext-free/.../CoreUpdaterImpl.kt:80-130`) only checks that the first 4 bytes say "ELF" before loading the file as code. HTTPS protects the download in transit, but if a release asset were ever replaced, through a mistake or a compromised GitHub account, every Lite user would run that code. The PPSSPP assets zip has the same gap.

**Fix.** When uploading a cores release, generate `cores-manifest.json` with `{abi, core, sha256}` for each file and build it into the APK. Check the sha256 before renaming the temporary file into place, and refuse the core on a mismatch. A small script in `scripts/` can produce the manifest.

## 7. MEDIUM: on Android 13+, games won't start without notification permission (Confirmed)

**Problem.** `GameInteractor.ensureNotificationsPermissionAvailable` (`lemuroid-app/.../shared/GameInteractor.kt:156-173`) blocks every game launch with a toast when notifications are denied. Players who said "Don't allow" can't play at all until they find the setting. This came from Lemuroid.

**Fix.** Let the game start anyway. The game service runs without a visible notification when permission is missing. Keep the card in the library that asks for it.

## 8. MEDIUM: backup and restore can stop halfway (Confirmed)

**Problem.** Export, backup and restore run in `GlobalScope` (`SavesSettingsViewModel.kt:134-157`). If Android kills the app during a long restore (swiped away, low memory), some saves have been replaced and others haven't, with no message. Each file is written safely on its own, but the restore as a whole isn't.

**Fix.** Run these jobs as WorkManager expedited work with a progress notification. For restore, extract everything to a staging folder first, then move it into place in one quick step at the end.

## 9. MEDIUM: a failed save on exit is silent (Confirmed)

**Problem.** `SavesManager.setSaveRAM` swallows write errors (`SavesManager.kt:33-49`). If the phone is full when you exit a game, the progress is lost and nothing tells you.

**Fix.** Return the result. When the exit save fails, keep the data in memory, retry once, and if it still fails show a notification ("Your save for X could not be written; free some space and open the game again").

## 10. MEDIUM: 69% of the app is untranslated in all 28 languages (Confirmed)

**Problem.** `values/strings.xml` has 532 strings. Every language checked (de, es, fr, pt-BR, ru, ja, zh-CN, ar) is missing about 366 of them, so a German phone shows a mix of German and English. The lint check that reports this (`MissingTranslation`) is turned off in `lemuroid-app/build.gradle.kts:163`.

**Fix.** Short term, limit `resourceConfigurations` to `en` until translations exist, so every user sees consistent English. Long term, use Weblate or Crowdin (both free for open source) and turn the lint check back on.

## 11. MEDIUM: the database can wipe itself if a future update has a schema mistake (Confirmed setting)

**Problem.** `LemuroidApplicationModule.kt:153` uses `fallbackToDestructiveMigration()`. Today's migrations from 8 to 13 are complete. But if a future version forgets one, Room silently deletes the library database, along with favourites, custom names, custom covers and play time. There is also no migration test.

**Fix.** Add a `MigrationTestHelper` test that migrates 8 → 13 using the exported schemas, which already exist in `retrograde-app-shared/schemas`. Then remove the destructive fallback, or limit it to downgrades with `fallbackToDestructiveMigrationOnDowngrade()`.

## 12. LOW: the lint error that keeps the lint check red (Confirmed)

`SkinLayoutEditorScreen.kt:108` reads `context.resources.configuration.orientation`. It is intentional, recording the orientation once when the editor opens, but lint flags it as an error, so lint can't be used as a release gate. **Fix:** read `LocalConfiguration.current.orientation` inside the same `remember { }`. Also fix or baseline the 38 warnings, mostly plural strings and two images without descriptions.

## 13. LOW: RetroAchievements sign-in can be lost silently (Confirmed code path; rare)

`RetroAchievementsTokenStore.createAndroidKeystoreCipherOrFallback` (`.../achievements/RetroAchievementsTokenStore.kt:118-147`) switches to a throwaway key if the Android Keystore fails. That fallback was meant for tests, but it also runs on real phones. On a phone with a broken keystore, the player is signed out after every restart with no explanation. **Fix:** use the fallback only in tests. On a phone, show "Couldn't store your sign-in securely" instead.

## 14. LOW: Android backup settings (Confirmed)

`allowBackup="true"` with no rules means Google backup copies the settings, including the encrypted RetroAchievements token. That token can't be decrypted on a new phone. Backup does not copy saves, because they live in the app's external files folder. Players may assume their saves are in their Google backup. **Fix:** add backup rules that exclude the RetroAchievements preferences. Say in the README and on the Saves screen that Android backup does not include saves.

## 15. LOW: the updater gives the wrong message if a non-app release is marked "Latest" (Confirmed)

`AppUpdater.fetchLatestRelease` reads `releases/latest`. When the `cores-2` release held the "Latest" flag, the app said "no connection". **Fix:** list releases and pick the newest `v*` tag that has the expected APK, and show "No app update found" instead of a connection error.

## 16. LOW: inherited Lemuroid code that blocks the main thread (Confirmed)

`ShortcutBindingUpdater.kt:48` and `InputBindingUpdater.kt:43` use `runBlocking` on the main thread while a gamepad button is being bound. The second one also starts work it never waits for. **Fix:** move both to `lifecycleScope.launch` and close the screen when the save finishes.

## 17. LOW: maintainability

`ArcaduneSkins.kt` (3,227 lines), `ArcaduneSkinView.kt` (3,074) and `SkinEditor.kt` (2,782) are the three biggest files, and the skin code holds 295 of the 338 style violations. **Suggestion:** split by job (layouts, placement, drawing, editor panels) next time that area changes, and run `ktlintFormat` once.

## Checked and found sound

- **Backup restore:** blocks malicious zip paths (`..`, absolute paths, escaping the folder) and caps size and file count (`SavesArchive.kt`).
- **PPSSPP assets unzip:** also blocks malicious paths.
- **Saves and save states:** written atomically (temporary file, then rename), so a crash mid-write never leaves half a file.
- **App updater:** checks GitHub's sha256 of the APK, and Android only installs updates signed with the same key.
- **Network:** plain HTTP is allowed only for `thumbnails.libretro.com` covers. Everything else is HTTPS.
- **RetroAchievements token:** AES-GCM with a key in the Android Keystore. Old plain-text tokens are migrated.
- **Hardcore mode:** locked in release builds (`RA_HARDCORE_APPROVED = false` in the generated BuildConfig).
- **Rewind memory:** capped at 60 snapshots or 48 MB.
- **Public deep link `arcadune://.../play-game/id/N`:** rejects bad input without crashing.
- **Lists inside dialogs:** all the remaining ones have a height limit. The 1.1.1 fix covered the only three dialogs with the nested-scroll crash.
- **R8 rules:** keep the classes used by reflection and serialization, so nothing breaks only in release builds.
- **Database migrations:** 8 → 13 are present, and the schemas are exported.

## Status after the fixes (same day, not released)

Every finding above was fixed in the code. Two more serious bugs were found while doing it, from your phone and a player's report, and fixed too.

### New: the library emptied itself ("games gone, Select ROMs directory never goes away")

- **What happened:** Android stopped letting Arcadune read the ROMs folder (the exact trigger is not known: the phone's log did not reach back far enough). Games then failed to start (the "Something bad happened" screen), and the next library scan could not list the folder. A folder that could not be listed was treated as **empty**, so the clean-up deleted every game, with favourites, play time and custom covers. Saves are separate files and were not touched.
- **Why choosing the folder again did not help:** the picker only asked Android for permission when the folder was *different* from the saved one, so picking the same ROMs folder never got the permission back.
- **Second way to the same result:** Factory reset, which the crash screen recommends, cleared the ROMs folder setting and then scanned: no folder, no files, every game deleted.
- **Fixes:**
  - a folder that cannot be listed now stops the scan, without any clean-up (`StorageAccessFrameworkProvider`);
  - a scan that saw no file at all never deletes a non-empty library (`LemuroidLibrary.shouldRunCleanUp`, tested);
  - choosing a folder always asks Android for permission, even the same folder;
  - factory reset keeps the ROMs folder;
  - the library shows "Choose your ROMs folder again" when the permission is gone, instead of games that crash;
  - picked cover images no longer request a lasting permission (they are copied into the app anyway).

### Findings 1 to 17

1. **Tests for the screens:**
   - `NoNestedScrollInDialogsTest` reads the source and fails on the 1.1.0 bug. It was proved by putting the bug back: the test failed and named the file.
   - `scripts/smoke-test.ps1` taps through every Settings screen and dialog, the library actions and the pause menu, in portrait and landscape, and fails on any crash.
   - The release rules are written down in `docs/RELEASE_CHECKLIST.md`.
   - Lint and ktlint are green; see 12 and 17.
   - CI: `checks.yml` runs ktlint, the tests and lint on every push.
2. **Save read errors:** a save that exists but cannot be read now stops the game from loading instead of starting it empty (`SaveReadException`). Every save that is replaced is first copied to `saves-previous/`.
3. **Double tap:** only one game can be starting at a time (`GameLauncher.tryStartLaunch`, tested). The game screen is started on the main thread and never from a closed screen.
4. **CI:** `publish.yml` is deleted. `checkstyle.yml` is replaced by `checks.yml`, which builds no release and publishes nothing.
5. **Shared save names:** games that share a save name get `saves/by-console/<console>/<name>.srm`. The old shared file stays with the game that wrote it last. `SaveFileLocatorTest` covers this.
6. **Downloaded cores:** every core and the PSP files are checked against SHA-256 fingerprints built into the app (`CoreFingerprints.kt`, made by `scripts/update-core-fingerprints.ps1`). A file that does not match is refused. `CoreFingerprintsTest` also checks that every core has a fingerprint.
7. **Notifications:** games start without notification permission.
8. **Restore:** everything is unpacked into a staging folder first, and saves are only replaced once the whole backup was read without a problem (tested).
9. **Failed save on exit:** it is retried, then a "Your game was not saved" notification tells the player.
10. **Translations:** the app ships English only until each language is complete (`resourceConfigurations`).
11. **Database:** `MigrationsTest` (Robolectric) upgrades databases from versions 8 to 12 to 13 and checks a game keeps its data. The library is only wiped when an *older* app is installed over a newer database.
12. **Lint:** the error is fixed. The accessibility, locale and API-level warnings are fixed. The remaining old warnings are recorded in `lemuroid-app/lint-baseline.xml`, so lint fails on any new problem.
13. **RetroAchievements sign-in:** no more throwaway key. If the phone cannot store the sign-in securely, sign-in says so.
14. **Phone backup:** the Saves screen says that Android's own backup does not include saves. A sign-in restored to a new phone already shows as signed out.
15. **Updater:** it picks the newest `v*` app release from the list, so a cores release marked "Latest" no longer hides it (tested). With no app release at all it says "up to date", not "no connection".
16. **Gamepad binding:** saved in the background, so the main thread never waits on storage.
17. **Style:** ktlint is at 0 violations, down from 338. The recorded layout data moved to `HandTunedLayouts.kt`, which is exempt from the line limit like `ShaderChooser.kt`. The rest was wrapped by hand; the controller art regenerated byte-identical, so no layout changed. Splitting the three biggest files was **not** done: it is a refactor with no change for players, best done the next time that code changes.

Test count: 174 unit tests (154 before), 0 failures.
